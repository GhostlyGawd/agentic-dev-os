# Agentic Development Operating System — Master Delivery Contract

This is the repository's controlling implementation contract. `docs/trace/master-compliance.json` decomposes it into 82 independently verified obligations.

## Required system

The repository must preserve product intent in PRDs; behavioral, architecture, interface, edge-case, and test contracts in specs; bounded execution in tickets and Ralph loops; module boundaries in a dependency graph; bidirectional requirement-to-outcome traceability; and structured evidence in events, metrics, dashboards, alerts, findings, decisions, archives, and CI history.

## Required lifecycle

PRD → spec → ticket → plan → approval when required → bounded implementation → verification → outcome review → metrics → completion → archive. Changes must update linked artifacts together. Ambiguous and cross-cutting work exits into an exception track.

## Required governance

Stable IDs, explicit acceptance criteria, file scope, stop conditions, risk tiers, digest-bound approvals, least privilege, shadow mode, architecture checks, public API discipline, tool naming rules, validation beyond tests, periodic harness audits, failure-to-guardrail conversion, and real user feedback outside the harness are mandatory.

## Required measurement

Instrument artifact lifecycle, loop lifecycle, agent actions, tests, CI, dependencies, reviews, interventions, approvals, trace changes, findings, reversals, archives, metrics, alerts, and growth conversions. Calculate task completion, first-pass success, intervention, retry depth, cost per success, lead time, spec adherence, trace coverage, regression rate, architecture violations, and event completeness.

## Required operations

Provide owners, templates, a complete example, selective test impact mapping, stale-artifact audits, active/archive separation, human-readable reports, a portable dashboard, threshold alerts, CI evidence artifacts, and reproducible local commands.

## Required growth system

Define audience, pain, hypothesis, positioning, messaging, organic channels, content, community, product-led sharing, SEO, conversion path, staged launch, adoption metrics, failure modes, weekly cadence, experiments, and copy-ready templates. Record funnel events without coupling the core to a publishing vendor; live adapters may be added when destinations and credentials are selected.

## Completion rule

Completion requires all 82 compliance records to be `Complete`, every implementation reference to resolve, every evidence test to exist, all trace records to resolve, all CI-equivalent local gates to pass, negative-path controls to be tested, and an end-to-end demo to generate metrics, alerts, and a dashboard.
