# Organic Growth and Distribution Strategy

## Positioning

Use AI agents without turning the repository into chaos. Connect intent, code, tests, and operational outcomes so teams can ship quickly without losing control.

## Initial audience

Start with AI-native product teams and platform engineers already experiencing spec drift, rework, or unclear agent scope. Lead with less rework and faster, safer execution—not governance as an abstract virtue.

## Growth loop

1. Name a specific failure mode.
2. Teach a useful method with a real artifact.
3. Let the reader clone or copy the artifact immediately.
4. Invite feedback through issues and discussions.
5. Turn recurring questions and failures into content, templates, and product improvements.

## Channel plan

| Channel | Native asset | Primary conversion |
| --- | --- | --- |
| GitHub | Starter repo, issues, examples | Clone or star |
| Technical articles | Failure analysis and tutorials | Visit quick start |
| Developer communities | Useful answers and case studies | Try a template |
| Search/docs | Long-tail how-to pages | Run `make demo` |
| Live sessions | End-to-end repo walkthrough | Adopt in shadow mode |

Participate before promoting. Every asset must remain valuable if the reader never adopts the repository.

## Content pillars

- Why AI-assisted repositories drift.
- PRD-to-test traceability in practice.
- Bounded agent loops and stop conditions.
- Measuring retries, intervention, and user outcomes.
- Architecture boundaries for agent-written code.
- Honest case studies: what failed and which guardrail fixed it.

## Conversion path

Useful post → README → `make demo` → adapt one ticket → shadow-mode trial → team adoption → public case study.

## Twelve-week launch

- Weeks 1–2: Publish the problem narrative, repo, and an end-to-end demo.
- Weeks 3–4: Publish traceability and bounded-loop tutorials; collect friction.
- Weeks 5–8: Release two case studies and improve onboarding from observed failures.
- Weeks 9–12: Host walkthroughs, publish benchmark results, and recruit design partners.

## Metrics

Track unique and returning visitors, GitHub stars and forks, template downloads, demo completions, community signups, subscribers, shares and mentions, trial-to-adoption conversion, content-to-signup conversion, first-ticket completion, week-four retention, questions answered, and case studies. Treat raw traffic as context; qualified adoption and retention are success.

## Weekly cadence

- Publish one durable technical artifact.
- Share one concrete example or finding.
- Answer community questions.
- Improve one onboarding surface.
- Interview one user or review one observed session.
- Review acquisition, activation, retention, and outcome evidence.

## Failure modes

Avoid multi-audience messaging, governance jargon, link-only community posts, vanity-metric optimization, premature community creation, and claims unsupported by a working artifact.
